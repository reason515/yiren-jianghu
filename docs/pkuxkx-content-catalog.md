# 1. 目录说明

本目录用于记录从 pkuxkx（参考代码库，`D:/code/xkx/pkuxkx-utf8`）筛选进入《一人江湖》的每一项候选内容。所有内容导入新仓库前必须先在此登记。

## 1.1 筛选标准

每一项候选内容按以下四个维度评估：

| 维度 | 说明 |
|---|---|
| 玩法价值 | 是否支撑核心循环（探索/成长/挂机/PVP/社区） |
| 依赖 | 依赖哪些已定系统或内容，缺失则优先级下调 |
| 移动端适配度 | 是否适合文字叙事 + 按钮交互 + 挂机模型 |
| 权利状态 | 机制借鉴 / 需改写 / 需授权（见 §2） |

## 1.2 决定状态

| 状态 | 含义 |
|---|---|
| 纳入 | 进入首版或当前切片 |
| 延期 | 认可价值，明确延后并注明触发条件 |
| 否决 | 不进入新游戏 |
| 待议 | 信息不足，待补充后再评 |

# 2. 权利登记流程

任何参考 pkuxkx 的内容进入新仓库前，必须按以下三类登记：

| 类别 | 处理方式 |
|---|---|
| 可借鉴机制 | 重新设计并实现为新游戏的结构化规则，标注来源文件 |
| 需改写的设定与文本 | 保留灵感来源，重新编写、重新命名并独立验收 |
| 需确认授权的代码或素材 | 未确认权利前不得复制进入新仓库 |

每项登记均须记录：来源文件、提取内容、依赖、权利状态、决定状态与理由。

# 5. 明确否决

| 条目 | 理由 |
|---|---|
| QQ 机器人 / BBS / IM | 时代与平台不符，论坛为受控纯文本社区 |
| 反机器人 daemon（`antirobotd.c`） | 服务端权威 + 邀请制封测天然控制 |
| 离线交易 / 玩家当铺 | 单角色 + 弱社交，无交易市场 |
| 实时相遇与共享世界 | 产品定位：在线但单人沉浸 |
| 原始命令行交互 | 结构化移动端 UI 替代 |
| LPC 运行时 / FluffOS | 新游戏不运行旧引擎 |
