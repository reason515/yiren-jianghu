# 1. 测量环境

- 本机 Windows 11 / Node v22.19.0 / pnpm 10；API 走真实 HTTP（127.0.0.1:3000）
- PostgreSQL 16 + Redis 7（Docker Desktop 容器，同机）
- 内容包：dev-pack@0.2.0；限流器关闭（`disableRateLimit`，压测专用选项，见 §5）
- 并发模型：200 个并发 fetch 持续 4s，统计 RPS / p50 / p95

# 2. API 吞吐基线（200 并发）

| 端点 | 请求数 | RPS | p50 | p95 | 说明 |
| --- | --- | --- | --- | --- | --- |
| GET /health | 17,650 | **4,354** | 43ms | 66ms | 纯路由（无 DB） |
| GET /ready | 10,364 | **2,556** | 73ms | 99ms | PG 探测往返 |
| GET /scene（鉴权+业务） | 7,490 | **1,839** | 107ms | 129ms | token 校验 + 内容包组装 + PG 查询 |

**结论**：单机 API 在 200 并发下业务吞吐 ~1,800 RPS、p95 < 130ms。封测 20–50 人在线峰值 QPS（每玩家每秒 1–3 次操作）远低于该量级，**单机（API 单实例）可支撑封测规模，无需预扩容**。p95 随 DB 依赖逐级抬升（43→73→107ms），瓶颈在 PG 往返而非应用逻辑。

# 3. 限流器行为（实测）

- 首次压测未关限流：`/health` 恰好成功 118 个请求 ≈ 120/分钟/IP 上限，其余全部 429——**限流器按预期生效**。
- 占位值 120/分钟/IP 为骨架值；正式值（按封测节奏调，如 60–120 请求/分钟）随 G3 迁移 Redis 限流时定，当前每进程内存令牌桶仅单实例有效。

# 4. Worker tick 成本

| 指标 | 实测 |
| --- | --- |
| 100 个 running 作业结算一轮 | 613ms |
| 每作业均摊 | **6.1ms**（事务 + FOR UPDATE + 技能/精写回） |

**结论**：每作业 < 7ms → 即使 500 个并发挂机作业，一轮结算 < 4s；60s 轮询间隔余量充足。Worker 单实例足够，瓶颈在 PG 写放大（每作业 2–3 条写），容量见 §5。

# 5. 容量预估（封测 20–50 人）

## 5.1 PostgreSQL

| 表 | 每玩家估算 | 50 人量级 | 说明 |
| --- | --- | --- | --- |
| accounts / sessions | 1 / 2 | ~100 行 | 可忽略 |
| characters | 1 | ~50 行 | 单角色约束 |
| character_skills | 武功数 ~6 | ~300 行 | 可忽略 |
| character_items | 10–30 | ~1,500 行 | 可忽略 |
| character_quests | 3–10 | ~500 行 | 可忽略 |
| afk_jobs | 挂机作业累计 ~50/月 | ~2,500 行/月 | 战报 jsonb，退役后按天归档 |
| pvp_matches | 每日 ≤5 + 赛季累计 | ~5,000/季 | 战报事件流 jsonb 偏大（百 KB/条），**建议 30 天后清理或转归档** |
| forum 四表 | 低频 | ~2,000 行 | 可忽略 |
| audit_events | 关键操作 ~10/日 | ~15,000/月 | 按需归档 |

**总容量**：50 人封测 3 个月，PG 数据 < 2GB（主要被 pvp 战报事件流与 audit 占据），默认 10GB 卷足够。

## 5.2 Redis

- 当前仅会话锁/心跳等轻量用途（挂机结算走 DB 轮询 + FOR UPDATE，未依赖 Redis 队列）。
- 预估 < 50MB。默认容器无压力；G3 将限流迁入 Redis 后仍远小于 256MB。

# 6. 结论与建议

1. **封测规模单机足矣**：API 1,800+ RPS、worker 6ms/作业，50 人远未触顶；上线部署沿用 `deploy/README.md` 单 API 容器方案。
2. **pvp_matches 战报事件流是主要增长项**：建议 G2 加入「战报 30 天归档」任务（worker 或定时 SQL）。
3. **限流值需按封测节奏定**：120/分钟/IP 仅骨架；G3 迁 Redis 分布式限流时校准。
4. **复测方法**：本报告数据由一次性脚本产出（未入库）；如需定期回归，可把压测脚本沉淀到 `scripts/bench/`（autocannon 或本脚本模式）。
