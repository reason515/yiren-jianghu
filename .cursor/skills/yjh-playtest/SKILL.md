# 《一人江湖》玩家试玩审计

## 定位

问的是：**玩家愿不愿意继续玩、卡在哪、和姊妹作比差在哪。** 不是「功能通不通」。

| 本 skill                          | 不是                                      |
| --------------------------------- | ----------------------------------------- |
| 新玩家视角体验审计（九维 + 证据） | `docs/beta-launch-checklist.md` 13 步冒烟 |
| 对照 xkx Web / pkuxkx **读码**    | 本机跑 FluffOS                            |
| 卡住记上手问题                    | 靠内部 ID / 设计者知识绕过                |

范例报告：`docs/playtest-audit-2026-08.md`。产出走 `yjh-design-docs` 的 **audit** 层。界面取证纪律见 `ui-visual-audit`（本 skill 管玩法/上手，不替代视觉走查）。

## 启动必读（每次重新 read，禁止凭记忆评文案/战报）

1. 本 skill。
2. `yjh-wuxia-copywriting`（评房间/对话/任务/战报原文时）。
3. `yjh-combat-presentation`（评战斗读感时，与上条同读）。
4. `yjh-mobile-ui`（30 秒承诺、离线回声、触控）。
5. 若打界面分：`ui-visual-audit`（截图 + CSS 探针，不单信视觉模型）。
6. 写报告：`yjh-design-docs`。对照读码前可扫 `docs/sibling-borrowings.md`。

默认**只出报告、不改玩法**。用户当次明确要求「边试边修」才改代码；机制/数值仍走 `yjh-mechanics-sync` + 另开 DC。

## 立场

- 假装没读过设计文档。知道「初试身手 / 王师傅 / 野狗」是设计者知识，试玩只跟**界面与文案**走。
- GuideTip 跳过/乱序后迷路 = 上手问题，不靠 `roomId`/`questId` 补航。
- 不把「内容少」写成缺陷——切片范围（DC-018）已定；只评**现有范围内**好不好玩、好上手。
- 不把 xkx 35 步命令教学或命令行搬回来（DC-003）。对照时写清三类：**对齐且更好** / **对齐但手感仍差** / **有意裁掉后留下的空档**。

## 九维（每维 1–5 + 证据）

原五维管「能不能玩、好不好点」；后四维管本项目相对 xkx 的独特承诺。内容密度并入可玩性（出村后还有没有目标）。

| 维度                 | 玩家问题                                       | 主要证据                                          |
| -------------------- | ---------------------------------------------- | ------------------------------------------------- |
| 可玩性               | 有没有「再点一下」的理由？闭环是否空转？       | 各段耗时与决策点；现有区/任务是否撑得住           |
| 合理性               | 世界、数值、任务因果是否自洽？                 | 学费/银两/怪强度/任务门槛 vs 建角赠予             |
| 上手难度             | 30 秒内能否知道「我在哪、下一步做什么」？      | `yjh-mobile-ui` 体验承诺；GuideTip 是否够用       |
| 操作便利性           | 关键动作几次点击、会不会找错面板？             | 学武/接任务/开战/挂机/买药点击深度                |
| 界面美观度           | 是否像行旅簿而非管理后台？                     | 截图 + CSS 探针（防把墨底判成白底）               |
| 叙事沉浸与文案神韵   | 房间/对话/任务/战报像不像在读武侠？            | 当场摘录原文；对照 wuxia-copywriting              |
| 战斗读感             | 一招是否闭环？着色/闲笔/人兽/悬念？            | 至少一场兽战 + 一场人战；对照 combat-presentation |
| 成长可见性与失败恢复 | 变强能否被感知？落败后知不知道回血/打工/再战？ | 学武前后差；故意输一场                            |
| 离线回声             | 挂机归来是「角色做过事」还是「数字 +338」？    | 生计/修炼/行侠各停一次，读战报叙事                |

## 试玩协议

### 环境

- **默认生产站** `http://117.72.34.43/`（玩家手感以线上为准）。预发布可用本地 Docker。
- **独立邀请码建新号**。`ALLOW_ANY_INVITE=1` 时任意码可登录，但**不要占用用户常用邀请码**（同码=同账号）。
- 视口 **390×844**；关键屏再 3x 截图。
- **低频操作**（生产限流约 120/分/IP）。自动化曾把自己打回登录页。
- 受控输入**优先真人打字**，不靠 CDP 灌值（conventions 坑 #26）。

### 路径（迷茫新玩家，卡住就算问题）

| 段             | 玩家目标                 | 卡住就算问题                                                       |
| -------------- | ------------------------ | ------------------------------------------------------------------ |
| 登录/建角      | 立名、分配四维、看懂序章 | 不知道点什么、四维无反馈                                           |
| 青石村         | 自己找到下一件该做的事   | GuideTip 跳过/乱序后迷路                                           |
| 学武           | 找到教头并学会一门       | 学费不够、找不到武馆、请教藏太深、门槛无解释                       |
| 首战           | 村外练手怪               | 必败无生计提示；或必胜无教学；战报不像武侠；时长远超短打           |
| 落败恢复       | 故意输或残血后自救       | 找不到运功（人物簿状态页，未学不显示）/吃药/歇脚；不知道可以先打工 |
| 生计           | 杂役/垂钓/采药           | 打不过却找不到打工；归来只有数字                                   |
| 出村入城       | 官道→城门→药铺/衙门      | 无动机出村；城内不知去哪                                           |
| 衙门/门派/支线 | 悬赏、拜师               | 门槛对不上成长                                                     |
| 挂机/论剑/地图 | 三种挂机 + 异步 PVP      | 入口找不到、战报不可读                                             |

某段因上游 P0 走不到：记「未实测 + 原因」，**不要编造分数**；门槛仍可作为合理性风险（非实测卡死）。

### 每段必记

耗时、点击次数、情绪（顺/迷/烦）、截图要点、是否违反「30 秒知道下一步」；房间/对话/战报各摘 1–2 句原文。战斗维看完一场兽战与一场人战的节奏再打分。离线回声：三种挂机各开一小段再停。

界面维：`getComputedStyle` + `document.fonts.check` + 滚动条规则，不单信视觉模型。

## 常见坑（试玩实战）

1. **生产限流 + CDP 灌值**：见 conventions #26。试玩用真人节奏；登录优先手打或 API+token，勿连打 snapshot。
2. **视觉模型把墨底判成白底**：必须 CSS 探针；`body`/`.app` 背景、`fonts.check`（XiaoWei / Noto Serif SC / LXGW）、scrollbar 规则。
3. **底栏挡住场景 chip**：村长等 NPC 要点不着时先 `scrollIntoView`，并记 P1（padding 不够）。
4. **GuideTip 低于 Sheet / 起程过场**：点「知道了」被拦截 → 上手问题，不是「引导没出」。
5. **请托 ≠ 接任务**：「请托」常只打开任务列表，须再点接受。
6. **「前往」不跨房寻路**：toast「路途尚远……」时按出口走，并记空档；勿用内部 roomId 瞬移。
7. **战斗显现期动作条锁定**：逃跑/回气可能要等显现行结束；失败句无下一步 = 失败恢复扣分。
8. **aria / Tab 泄漏内部 ID**：`village_square`、`人物2`（计数徽章拼读）记 P1/P2，勿当房名教玩家。
9. **未走到的段不要编分**：上游 P0 阻断时写「未实测」，门槛可进合理性风险。
10. **修复复核**：同一新号路径重跑；先核对上一轮 P0，再打九维。通过项不要当新缺陷重开。

## 不做什么

- 不修 bug、不调数值、不重写文案（发现了只分级），除非用户当次要求边试边修。
- 不把「内容少」写成缺陷；不加区加门派来「凑密度」。
- 不搬回 35 步命令教学或命令行。
- 不在生产刷高频请求、不占用常用邀请码。
