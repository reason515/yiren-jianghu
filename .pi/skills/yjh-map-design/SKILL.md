# 《一人江湖》地图设计规范

## 定位与来源

地图不是流程图，而是玩家辨识方位、选择去处的**地理示意图**。本规范移植自 `D:\code\sanguo-mud\.pi\skills\hanmo-svg-map\SKILL.md`（汉末八向舆图），按本项目架构重写：逻辑导航（连通性/BFS/白名单）在 `game-core/map.ts`（C10），本 skill 定义**表现层地图数据契约**（布局、出口方向、绕行、世界地理语义）与渲染/校验/交互基线。

视觉 token 待 E 阶段前端基线定义后补充；数据契约与校验方法论先行。

## 1. 地图层次与多视图一致性（最重要）

同一张路网出现在三个视图，玩家来回对照——**所有视图对"能去哪、往哪个方向"的答案必须一致**，否则玩家会怀疑世界不可信（典型症状："地图没路、方位图却有路"）。

```text
场景方位图（当前房间直连出口）  ─┐
区域地图（全局路网）            ─┼─ 共享同一出口真相（rooms.exits / C10 room graph）
世界总览（跨区域方位）          ─┘
```

硬性规则：

1. **出口真相单一来源**：场景方位图与区域地图都从同一出口定义派生（C10 `RoomNode.exits`）；任何视图不得单方面增删出口。
2. **可前往 = 可移动**：地图节点标"可前往"就必须真实可移动（目标房间存在且 C10 可达）；点击执行移动而非只弹提示。当前节点判断用实时位置，不用渲染时闭包。
3. **地标与房间分离**：地图可含地标（未开放区域、装饰性地名），但**不得与房间节点连线**——地标路线会被误认为可通行出口。地标点击提示"此处暂不可进入"。
4. **首个可玩区域必须有区域总览**：玩家需要"我在哪、边界在哪（城门/入城方向）"的全局认知；只有方位图会"走不到头"。

## 2. 区域地图数据契约：语义网格，而非像素

设计者维护可读的地理拓扑数据；像素由渲染器统一换算。`grid` 是地图数据的一部分，供内容工具、后端与地图组件共同消费。

```js
const MAP = {
  grid: { x: 142, y: 106 }, // 同一地图内统一的网格节距
  nodes: [
    { id: "alley", name: "市北杂巷", grid: [2, 0], state: "current" },
    { id: "tao", name: "陶肆·徐", grid: [2, -1], state: "visited" },
    { id: "wine", name: "酒肆后巷", grid: [2, 1], state: "visited" },
  ],
  edges: [
    // dir 是玩法出口真相（与 C10 exits 一致）；via 可选，用于避开建筑群
    { from: "alley", to: "tao", dir: "north" },
    { from: "alley", to: "wine", dir: "south" },
  ],
  currentId: "alley",
};
```

- 节点中心只能落在整数 `col/row` 语义网格上；禁止散落像素坐标。
- 直连出口的目标网格方向必须与 `dir` 一致（距离可大于一格）；折线 `via` 只负责绕线，每个相邻点仍须八向，且不得改变起点终点表达的出口方位。
- 与 C10 的关系：`MAP.edges` 必须与 `RoomNode.exits`（逻辑导航）一致——C10 管可达性，MAP 管布局，二者共享出口真相。

八向映射：

```js
const DIR = {
  north: [0, -1],
  northeast: [1, -1],
  east: [1, 0],
  southeast: [1, 1],
  south: [0, 1],
  southwest: [-1, 1],
  west: [-1, 0],
  northwest: [-1, -1],
};
```

方向自洽：若 A 在 B 的东北，则 A→B 只能 northeast（或反向）；双向出口同时推导，避免"正东/正北"互相矛盾。

## 3. 开发期校验器（建议并入内容包 validator）

实现地图组件时保留以下校验；内容包层面可先做前两条（数据即校验）：

1. **节点网格重叠**：`grid` 唯一。
2. **非八向线段**：每一段 `dx===0 || dy===0 || dx===dy`；`via` 与端点同规则。
3. **路线穿节点**：线段与矩形相交（Liang–Barsky 或等价），节点外扩 8px 安全边界——禁止用"肉眼看着没穿过"代替。
4. **出口方位一致**：`dir` 符号 = `sign(dest − from)`。
5. 浏览器验收统计：节点/边/**可见边数**（`getTotalLength()>30`）/重叠数/穿节点数/非八向段数/console errors——重叠、穿节点、非八向、console errors 必须为 0，可见边数必须等于边数。

## 4. 渲染规则

- 先边后点；端点**裁切到节点框外**（否则箭头与路线末端被节点遮住）；当前出口箭头只加最后一段，`refX=10` 尖端接触目标框；普通边不加箭头（避免"单向路"误解）。
- 动态 viewBox：覆盖全部节点框并保留 80–110px 留白（**含负坐标**）——过小/静态 viewBox 会裁剪边缘节点，边线端点悬空。
- 只在顶部固定一个"北"标，**不在每条边上标方向文字**。
- 区域用淡金小标题划分空间层次（如"宫禁/市井/河渡/南郊"），不画假城墙假道路。

## 5. 世界地图（天下图）语义

回答"我在何处、去那里要经过哪里、那是城还是关渡"，不是把已知地点画成枢纽的放射状出口。

```js
const WORLD = {
  nodes: [
    { id: "capital", kind: "metropolis", geo: [0, 0], scale: "capital" },
    { id: "pass", kind: "pass", geo: [-155, -14], scale: "pass" },
  ],
  roads: [
    // 道路链；无直连边就不得画直达线
    { from: "capital", to: "pass", mode: "road" },
  ],
};
```

1. **方位与远近**：`geo` 相对地理坐标，北在上；间距表达 近郊/一程/远行 层级；无可靠距离只标层级，不伪造里数。
2. **道路链 ≠ 直达**：线只表示相邻行路段；跨区域目的地沿道路逐段可追溯；中继节点（关隘/渡口/郡城）不可省略。
3. **节点规模**：都城大节点、郡城/县城中节点、关塞菱形、渡口/寺观/山岳小节点；**图例必须解释**。规模只表达聚落等级，不暗示战力或可达性。
4. **虚构边界**：未定位的地点标"方位未明"，不得编造坐标、距离或道路。
5. **交互**：渲染器只消费 nodes/roads，自动算 viewBox；允许缩放、拖拽、滚轮、双指缩放与"回到当前位置"；点选未开放节点只展示地理与道路信息，不能伪装成传送。

## 6. 交互与无障碍基线

- SVG 外层 `touch-action:none`；拖拽 + 滚轮/双指缩放（0.8–3x）；"缩小/放大/回到位置"为文字按钮，触控区 ≥44px。
- 节点 `role="button"` + 中文 `aria-label`，Enter/Space 可激活。
- 390×844 视口验证：无横向页面溢出、无 console error。
- 不用 dagre 渲染地理图；dagre 仅用于任务链/系统流程等非地理图。

## 7. 内容包落点（D/E 阶段接线）

- 房间布局数据（grid 坐标）随 D 阶段内容进入内容包：rooms 增 `grid` 字段，或新增 `maps/*` 集合（区域图/世界图数据），由内容包 Schema 与校验器接管（第 3 节校验并入 `validate.ts`）。
- 落地顺序建议：先场景方位图（复用 C10 exits）→ 区域总览 → 世界总览；首个可玩区域必须有区域总览。
- 地图上的地标/区域标签文案遵循 `yjh-wuxia-copywriting`。

## 8. 检查清单

- [ ] 每个节点唯一 `grid`，像素统一换算；无散落像素坐标。
- [ ] 每条出口有明确 `dir`，与网格几何方向一致；双向关系自洽。
- [ ] 绕行用 `via`（八向折线），不改变出口方位语义。
- [ ] 节点不重叠、边不穿非端点节点；可见边数 = 边数。
- [ ] 场景方位图 / 区域图 / 世界图出口真相一致（与 C10 exits 同一来源）。
- [ ] 地标不与房间连线；"可前往"节点点击真实移动（实时位置判断）。
- [ ] 动态 viewBox（含负坐标留白）；固定北标；无逐边方向文字。
- [ ] 缩放/拖拽/回到位置/键盘激活可用；44px 触控。
- [ ] 世界图：道路链可逐段追溯、节点规模有图例、虚构地点未编造坐标。
